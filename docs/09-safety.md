# 09 安全设计

> 安全不是“功能”，是贯穿 App、服务端、适配器、rl_sar、机器人固件的**分层防御**。
> **App 不是安全边界**：看门狗/急停/限位/仲裁必须在机器人端实现；协议强制安全语义，
> CTS 的 P0 安全组是“接实机”的硬门槛。生产 Agent 由厂商/社区按
> [18 实现指南](18-protocol-implementation-guide.md) 实现并自证。
> 对抗测试见 [14-adversarial-verification.md](14-adversarial-verification.md)。

## 1. 安全目标

1. **不失控**：任何软件/网络/单点故障都不能让机器人持续执行危险动作。
2. **可停止**：操作员随时能触发急停；急停不依赖视频/App 存活。
3. **不误动**：未经配对/未使能/无死手时不得运动；高风险动作需确认。
4. **可追溯**：所有命令、状态切换、故障有日志与时间戳，事故可复盘。
5. **物理兜底**：软件全部失效时，机器人固件/硬件急停仍能停止。

## 2. 分层防御

```
第 5 层：硬件急停 / 断电 / 物理围栏              ← 最终防线（不可软件绕过）
第 4 层：机器人固件/MCU 看门狗（命令超时清力矩）  ← 例如 L4W4：命令中断约 2 s 下趴
第 3 层：rl_sar/部署框架安全态（Passive/GetDown/力矩限幅）
第 2 层：Agent 安全层（校验/仲裁/看门狗/急停锁存/安全动作）
第 1 层：App 安全交互（死手、确认、失焦清零、断链提示）
```

原则：**低层不依赖高层**；高层失效时低层必须仍有效。任何“安全”只在上层实现，视为缺陷。

## 3. 安全不变式（与 14 文档一致）

| 编号 | 不变式 |
|---|---|
| I1 | 无有效控制输入超过 300 ms → 安全态；P99 停止延迟 ≤ 400 ms |
| I2 | 输出命令始终在能力声明与硬件限幅内 |
| I3 | 急停锁存，必须显式复位；不依赖 App/视频 |
| I4 | 控制/配置/地图不可重放/篡改/伪造 |
| I5 | 策略异常（NaN/Inf/饱和/陈旧/超时）≤300 ms 进入安全态 |
| I6 | 单控制者；观察者不可发控制 |
| I7 | 视频/深度/地图/日志的资源消耗不影响控制时效 |
| I8 | 密钥/日志/录像不泄露 |
| I9 | 时钟异常不导致误停/漏停 |
| I10 | 物理急停/断电/固件超时在任何软件崩溃下有效 |
| I11 | URDF 模型/关节顺序/状态仅用于显示与提示；关节命令的最终限位以机器人侧为准；模型或状态不一致时禁止运动渲染与关节命令 |

## 4. 状态机

### 4.1 会话状态

```
Idle → Discovered → Authenticating → Connected(Ready) → Armed(Control) → Safe(Estop/ Fault)
                 ↘ AuthFailed                       ↘ Viewer(只读)
```

- `Connected` 后仍不能运动；需 `SESSION_CTRL(claim)` + `arm`（显式使能）。
- `Safe` 状态下只接受 `release_estop` 流程；断开/超时回到 `Idle`。
- 第二控制者被拒绝或降级为 `Viewer`；控制权转移需先释放。

### 4.2 控制/机器人状态

```
Disarmed → Armed → Moving → SafeStop(damping/zero) → Disarmed
                    ↘ EstopLatched → (显式复位) → Disarmed
```

- `Armed` 是允许下发运动命令的唯一状态；从 `SafeStop` 恢复必须重新 `Arm`。
- 机器人原生 FSM（如 rl_sar 的 Passive/GetUp/GetDown/Locomotion）由适配器映射；
  rl_sar 的 `Locomotion→Passive` 注释缺口由 Agent 的 `safe_action(damping)` 补足（见 13）。

## 5. 看门狗与死手

| 看门狗 | 超时 | 动作 |
|---|---|---|
| 控制帧 TTL | 200 ms | 丢弃迟到帧；不执行 |
| 链路看门狗 | 300 ms | 零速；上报 |
| 安全态升级看门狗 | 1 s | 阻尼/安全动作；请求 GetDown |
| 状态新鲜度（rl_sar 补丁） | 500 ms | 进入安全态（防止“盲走”） |
| 策略推理看门狗 | 2×策略周期（如 100 ms） | 安全态；禁止自动恢复 |
| 机器人固件看门狗 | 由厂商定义（L4W4 约 2 s，需实测） | 清力矩/下趴（最终软件兜底） |
| 物理急停 | 硬线 | 断电/抱闸（最终防线） |

**死手（hold-to-run）**：

- 默认要求按住指定键（如 LB）才允许运动；松开/失焦/断连立即零速；
- App 与 Agent 双重实现：App 在 `flags.deadman=0` 时清零通道；Agent 看到 `deadman=0` 直接零速；
- 死手按键可配置；高风险形态（机械臂/无人机）强制开启。

## 6. 急停（E-stop）

### 6.1 语义

- **立即**（≤300 ms）进入阻尼/零输出；锁存；禁止所有运动命令与模式切换；
- 只有显式复位流程（App 二次确认 + Agent 复位）才能退出；复位后需重新 Arm；
- 急停通道独立于视频/地图；`ESTOP` 消息可靠发送并重复，直到确认。

### 6.2 各层实现

| 层 | 实现 |
|---|---|
| App | 常驻红色按钮；二次确认；显示机器人侧确认状态；断链时提示“按物理急停” |
| Agent | 收到 ESTOP → 锁存 → `adapter.safe_action(estop)`；本地看门狗独立于网络 |
| rl_sar | 补丁新增 `ForceSafeDamping()`（kp=0/kd=8 立即）；036 的 Locomotion→Passive 缺口必须由补丁补 |
| 机器人固件 | 命令超时清力矩/下趴；硬件急停直接断电/抱闸 |

> 036 当前文档推荐的 `LB+RB` 急停**未在 FSM 实现**（RL-01）；在补丁落地前，急停只能保证
> Agent 侧零速/阻尼（若适配器已实现），上线前必须完成补丁并验证。

## 7. 输入仲裁

优先级：**本地硬件急停 > RC 本地输入 > 网络遥操作 > 自主/导航**。

- RC 最近 500 ms 有活动（轴超阈值/按键）→ 网络抑制，并提示操作员；
- 切换来源时：清零积分/平滑/历史/输出队列，限斜率过渡；
- 双输入同时存在时不允许“叠加”；仲裁器在控制周期内完成；
- rl_sar 036 的 200 Hz RC 重写问题必须由补丁在 `RobotControl()` 内解决，不能只覆盖 `GetState()`。

## 8. 命令校验与限幅

- 会话/角色/状态检查；模式白名单；通道范围；变化率限制（斜率/加速度）；
- **关节命令**：`joint_position/velocity/effort/trajectory` 以 URDF 限位 + 适配器限幅双重校验；
  URDF 限位仅用于 App 显示/输入约束，**机器人侧/适配器仍是最终保护**；URDF 缺失限位时禁止关节命令；
- 指令 TTL；防止 NaN/Inf；防止整数溢出/回绕；(app) 与 Agent 双重校验，适配器第三次；
- 越界命令拒绝并计数/告警，不静默 clamp 后放行（除非显式配置）；
- 控制频率固定（100 Hz），不随网络抖动；网络包只更新“目标”，由控制周期消费最新值。

## 10. 失败场景与安全行为

| 场景 | 期望行为 |
|---|---|
| App 崩溃/被杀/断网 | 零速；安全态；重连后需重新 Arm |
| Agent 崩溃 | 机器人固件看门狗清力矩/下趴；systemd 拉起后安全态 |
| rl_sar 崩溃 | 同上；补丁/Agent 上报 |
| 状态断流 | 安全态（不盲走） |
| 策略异常/卡顿 | 安全态；禁止自动恢复 |
| 手柄断连/多手柄冲突 | 零输入；提示；主控槽位保持 |
| Wi-Fi 抖动/AP 掉电 | 看门狗零速；恢复后重新 Arm |
| 低电/高温 | 降级；提示；可配置自动安全停车 |
| 配置/模型错误 | 拒绝启动/拒绝进入运动；保持安全态 |
| 模型包篡改/关节顺序不符 | 拒绝渲染与关节命令；控制其他通道可继续 |
| 状态断流/时间戳异常 | 模型冻结/置灰；机器人侧看门狗独立生效 |
| 时钟异常 | 看门狗/重放正确；录制标记异常 |
| 物理急停 | 立即生效；软件不得抑制 |

## 11. 运行安全流程

- **上电**：机器人默认 Passive/Damping；Agent 启动安全态；不自动 Arm。
- **起飞/站立前**：检查急停、电量、地图/感知、操作员就位；App 显示检查清单。
- **测试分级**：数字孪生 → 台架（架高/限位/限流）→ 实机低速 → 正常。
- **交接/结束**：先安全停车、Disarm、释放控制；长时间不用断电。
- **事故复盘**：日志 + 录像 + 时间轴（命令/状态/FSM/网络）联合分析。

## 12. 安全验证

- 安全不变式 I1–I10 全部通过（见 14 文档）；
- 每个失败场景有自动化/半自动化用例与录像；
- 发布门禁：P0 安全用例全绿；未验证项列入发布说明；
- 硬件急停/断电测试必须实机执行，不能只做仿真。
