# 00 需求、范围与约束

## 1. 一句话目标

Uni-RoboController 是一个**开源机器人遥操作协议 + Android 操作端 + 一致性测试（CTS）**项目：
手机通过局域网自动发现机器人，低延迟看视频、用手柄遥控、查看机器人状态；
机器人端由厂商/社区按标准协议按需实现，项目提供 **mock 与最小参考 Agent** 作为活文档，
并用 CTS 保证各实现可互操作、安全语义一致。

> 范围收敛决策见 [ADR-0014](adr/0014-scope-app-protocol-cts.md)；协议实现指南见
> [18-protocol-implementation-guide.md](18-protocol-implementation-guide.md)。

## 2. 用户与场景

| 角色 | 场景 | 关键诉求 |
|---|---|---|
| 机器人厂商/开发者 | 给自家机器人加手机遥控 | 协议清晰、接入成本低、有参考实现与测试 |
| 操作员 | 室内遥操作、数据采集 | 低延迟画面、手柄顺手、状态直观、断线安全 |
| 开源贡献者 | 适配新机器人/手柄/传输 | 插件接口清晰、CTS 可自测、mock 可开发 |
| 算法工程师 | 采集演示数据（v1.1） | 视频/深度/点云/控制记录，时间戳可对齐 |

典型场景：

1. 手机连接机器人 Wi-Fi（或同一局域网），**自动发现**并配对。
2. 全屏视频 + 虚拟摇杆/蓝牙手柄控制机器人移动与动作。
3. 加载机器人 URDF 模型，实时同步关节与根位姿。
4. 网络抖动/断开时，机器人端自动安全停车，App 提示并可自动重连。
5. 开发者用 mock/最小参考 Agent 在没有真实机器人的情况下完成 App 开发与协议验证。
6. 厂商实现自己的 Agent 后，用 CTS 自测并登记到兼容列表。

## 3. 交付边界（B 方案）

### 3.1 本项目交付

| 类别 | 内容 |
|---|---|
| 协议 | 线上协议 v1（[03](03-protocol.md)）、能力描述、模型包格式、实现指南（[18](18-protocol-implementation-guide.md)）、测试向量 |
| 客户端 | Android App（v1 基础档）：发现/配对/会话/控制/遥测/视频/URDF 状态/手柄/安全交互 |
| 一致性测试 | CTS 静态组 + 动态组（P0/P1），报告格式与接实机门槛 |
| 参考实现 | mock 服务端（全协议 + 故障注入）、最小参考 Agent（单形态/单相机/基础档，x86_64+aarch64） |
| 工具 | `codec_ref`、`urdf_bundle`、`packet_viewer`、`latency_test` |

### 3.2 本项目不交付（由厂商/社区实现）

- 生产级机器人 Agent、多形态适配、rl_sar 补丁、完整 SLAM/点云地图实现、机械臂关节控制完整链路；
- v1 的 iOS/桌面/Web 客户端（跨平台后置）；
- 机器人端安全认证/认证体系（项目只定义协议安全语义与 CTS）。

### 3.3 安全责任边界

- **App 不是安全边界**：看门狗、急停、限位、仲裁、固件超时必须由机器人端实现；
- 协议强制安全语义；CTS 的 P0 安全组是“接实机”的硬门槛；未通过不得运动；
- 文档与 Release Notes 明确“参考实现仅用于开发/验证，不保证生产安全”。

## 4. 功能需求

### 4.1 v1 基础档（必须）

#### 4.1.1 发现与配对
- 局域网自动发现：UDP 广播 + mDNS（mDNS 在 M1 完成）；二维码/手动 IP 兜底。
- 配对秘密（QR/PIN）、认证、单控制者、只读观察者（可选）、重连。

#### 4.1.2 控制与手柄
- 物理手柄：多型号、多手柄、热插拔、震动；屏幕虚拟手柄兜底。
- 手柄映射可配置（死区/反向/曲线/组合键），按“手柄型号 + 机器人”保存、导入导出。
- 能力描述驱动的动态控制界面；速度/动作接口（joint_position 等增强档）。
- 安全交互：死手、急停、失焦清零、断链提示。

#### 4.1.3 视频
- 至少一路彩色视频，H.264 硬解；可配分辨率/帧率/码率/GOP（服务端能力协商）。
- UDP 低延迟通道：分片 + FEC + 关键帧恢复；自适应码率与统计（延迟/丢包/码率/FPS）。

#### 4.1.4 遥测与状态
- TELEM 20 Hz：FSM/模式、命令回显、链路、故障、电量；
- URDF 模型包下载/哈希校验 + MODEL_STATE（根位姿/关节）30 Hz 渲染。

#### 4.1.5 管理
- HTTP 管理接口：info/caps/config/logs/files/health；模型包下载；Token 认证。

### 4.2 v1.1 增强档（按能力协商）

- 深度图传输与 App 伪彩显示；客户端 GPU 反投影实时点云。
- 体素地图 + 2D 占据栅格：增量瓦片下发、App 3D 渲染、测量、离线保存。
- 关节/笛卡尔命令接口（机械臂/人形臂）；策略/RL 状态集成（rl_sar 社区示例）。
- 多相机、录制导出。

### 4.3 跨平台（v1.x/v2，后置）

- v1.x：iOS/桌面客户端（Tier A）；v2：Web 受限客户端（Tier B）。
- 详见 [17-cross-platform.md](17-cross-platform.md)。

### 4.4 rl_sar 集成（社区/合作示例，非核心承诺）

- 项目保留 [13-rl-sar-bridge.md](13-rl-sar-bridge.md) 的设计作为**社区示例/可选适配**；
- 欢迎厂商/社区按协议实现并提供 rl_sar 适配，登记到兼容列表（项目不背书质量）。

## 5. 非功能需求

| 类别 | 指标 | 说明 |
|---|---|---|
| 视频延迟 | 720p60 端到端 ≤ 100 ms（目标 80）；1080p30 ≤ 120 ms | 5GHz Wi-Fi、无拥塞、参考实现 |
| 控制延迟 | App 采集→机器人执行 ≤ 40 ms（中位数） | 控制帧 100 Hz |
| 控制频率 | 50–250 Hz 可配，默认 100 Hz | 不随视频帧率变化 |
| 安全响应 | 断链/看门狗 ≤ 400 ms 内安全停车 | 机器人端独立实现，CTS 验证 |
| 视频抗丢包 | 3% 丢包可恢复（关键帧 ≤ 2 s） | FEC + 关键帧请求 |
| 地图规模（增强档） | ≥ 200 m²、≥ 200 万体素 | 5 cm 体素 |
| App 性能 | 100 万点 ≥ 30 FPS；内存 ≤ 400 MB | 中端 2022 年手机 |
| 启动 | App 冷启动到可连接 ≤ 2 s | |
| 兼容性 | 第三方服务端通过 CTS P0 后可互操作 | 不用逐家适配 App |

## 6. 约束与假设

- **v1 客户端仅 Android**（`minSdk 26`）；共享层按 KMP-ready 设计，跨平台后置。
- **仅局域网**：不实现 NAT 穿透；后续可选 WebRTC/WebTransport 插件。
- **机器人端由第三方实现**（厂商/社区）：本项目提供协议、CTS、mock、最小参考 Agent，不提供生产 Agent。
- 机器人端目标：Linux **x86_64 与 aarch64（ARM64）**，不支持 32 位 armv7；无硬编时软编兜底。
- 开源许可证以 **Apache-2.0** 为目标；依赖需满足许可与专利政策（见 12 文档）。
- **安全边界**：App 不是安全边界；协议安全语义 + 机器人端实现 + CTS 门槛。
- 架构与模块边界见 [01-architecture.md](01-architecture.md)。

## 7. 术语

| 术语 | 含义 |
|---|---|
| App | Android 客户端（v1） |
| 服务端 / Agent | 机器人端实现，响应协议；本项目只提供 mock 与最小参考 Agent |
| 能力描述 / Capability | 服务端自描述 JSON：形态、控制模式/接口、动作、限幅、超时、安全、遥测、流、地图、模型 |
| 命令接口 | velocity / joint_position / joint_velocity / joint_trajectory / cartesian_pose / action |
| CTS | 一致性测试套件（Conformance Test Suite） |
| 模型包 / Model Bundle | URDF 转换后的 `model.glb + model.json + hash` |
| MODEL_STATE | 根位姿 + 关节位置实时状态，驱动 URDF 模型 |
| 基础档 / 增强档 | v1 必选能力 / v1.1 按能力协商的可选能力 |

## 8. 成功标准

### 8.1 v1（基础档 + CTS + 参考实现）

1. Android App 通过自动发现→配对→控制→遥测→视频→URDF 状态全链路，与 mock/参考 Agent 跑通。
2. CTS 静态组 + 动态 P0 组全绿；P1 组（遥测/视频/模型/故障注入）全绿。
3. 第三方按 [18 实现指南](18-protocol-implementation-guide.md) 能在 1 天内实现 Level 0–1 并跑通 CTS 基础组。
4. 安全不变式 I1–I11（09/14 文档）在 mock 与参考 Agent 上通过；断链 ≤400 ms 停、E-stop 锁存。
5. 视频 720p60 端到端 ≤100 ms（LAN，参考实现）。
6. URDF 四类模型（四足/人形/轮足/机械臂）加载与 30 Hz 状态同步、60 FPS 渲染。
7. 文档、mock、参考 Agent、构建脚本齐全；外部开发者按文档跑通 mock 全链路。

### 8.2 v1.1（增强档）

- 深度/点云/地图/关节命令按能力协商可用；增强档 CTS P2 组通过。
- rl_sar 社区示例（如有）通过基础档 CTS；项目不背书生产安全。
