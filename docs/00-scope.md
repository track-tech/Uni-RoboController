# 00 需求、范围与约束

## 1. 一句话目标

做一个**开源、局域网优先、客户端分级跨平台**的机器人遥操作平台：手机/平板/桌面连上机器人后，
能低延迟看视频、用手柄遥控、查看深度与点云地图；同一套 App 通过“能力描述 + 适配器”
支持多种形态的机器人。

## 2. 用户与场景

| 角色 | 场景 | 关键诉求 |
|---|---|---|
| 机器人开发者 | 实验室/室内调试 | 快速接新机器人；可改视频管线；能看传感器数据 |
| 操作员 | 室内遥操作、数据采集 | 低延迟画面、手柄顺手、地图可读、断线安全 |
| 算法工程师 | 采集演示数据、回放 | 视频/深度/点云/控制记录，时间戳可对齐 |
| 开源贡献者 | 适配新机器人/手柄/传输 | 插件接口清晰、文档完整、mock 可开发 |

典型场景：

1. 手机连接机器人 Wi-Fi（或同一局域网），自动发现并配对。
2. 全屏视频 + 虚拟摇杆/蓝牙手柄控制机器人移动。
3. 切换到地图页查看三维点云、占据栅格与机器人位姿。
4. 网络抖动/断开时，机器人自动安全停车，App 提示并可自动重连。
5. 开发者用 mock 机器人 + 桌面工具在没有硬件的情况下开发 App。

## 3. 功能需求（v1）

### 3.1 连接与会话
- 局域网自动发现（mDNS + UDP 广播兜底）、扫码配对、手动 IP 直连。
- 会话握手、能力协商、协议版本协商、单操作员锁（可选只读观察者）。
- 断线自动重连；机器人侧看门狗安全停车。

### 3.2 视频
- 至少一路彩色视频，H.264 硬编硬解，可配分辨率/帧率/码率/GOP。
- 可插拔媒体传输：默认 UDP 低延迟通道；预留 WebRTC 传输插件。
- 自适应码率与关键帧恢复；统计信息（延迟、丢包、码率、FPS）。

### 3.3 深度与点云
- 深度图传输（Z16 或降采样/压缩），App 显示深度伪彩与数值。
- App 端由深度 + 内参反投影生成实时点云（可选机器人端点云流）。
- 机器人端点云地图：体素化、瓦片化、增量下发；App 三维渲染、图层、测量、离线保存。
- 可选 2D 占据栅格叠加显示。

### 3.4 控制与手柄
- 物理手柄：多型号、多只手柄同时连接、热插拔、震动反馈。
- 屏幕虚拟手柄：双摇杆、扳机、自定义按钮布局。
- 手柄映射可配置（死区/反向/曲线/组合键），按手柄型号 + 机器人型号保存、导入导出。
- 能力描述驱动的动态控制界面：四足/轮式/机械臂/无人机等形态使用不同布局，但共用同一命令通道模型。
- 安全：死手开关、看门狗、急停、限幅、模式状态机。

### 3.5 管理
- App 内查看机器人配置、日志、录像文件；触发/停止录制；导出诊断包。
- 机器人端配置通过 YAML + Web/HTTP 管理接口维护（v1 以文件为主）。

### 3.6 rl_sar 兼容（首要集成目标）
- 兼容 [fan-ziqi/rl_sar](https://github.com/fan-ziqi/rl_sar)（Apache-2.0）：App 可作为 rl_sar 机器人（如 zhinao L4W4）的**远程遥控输入源**，替代/并存于物理 RC。
- 支持 rl_sar 的 FSM 动作：站立（GetUp）、趴下（GetDown）、被动（Passive）、RL 运动（Locomotion）、模型/技能切换、导航模式开关。
- 支持策略运行状态遥测：FSM 状态、当前模型、命令 (x,y,yaw)、关节 q/dq、IMU、推理耗时、链路与队列状态。
- 支持数据录制：视频/深度/点云、App 控制帧、机器人状态、FSM 事件、RL 动作（可选）按统一时间轴记录，可导出给离线分析/训练管线。
- 不要求兼容宇树 SDK；不直接链接任何机器人厂商 SDK（由 rl_sar 或机器人侧适配器负责）。

### 3.7 URDF 模型加载与状态同步
- 目标机器人不限定具体型号：**任意四足、人形、轮足、机械臂**（以及移动机械臂）均可接入。
- App 可加载机器人 URDF 转换后的模型包（glb + 元数据），按遥测实时同步根位姿与关节角，
  在 3D 视图中渲染机器人状态；支持本地导入 URDF/zip 用于离线预览。
- 模型包由机器人 Agent 提供（或开发者预生成），带 SHA-256 哈希与版本；App 校验后缓存。
- 模型与状态解耦：没有 URDF 时控制仍可用，退化为“关节条 + 简化骨架”显示。
- 关节顺序/限位以 URDF 为准，与 capability、遥测三者一致；不一致时禁止运动渲染并告警。

### 3.8 客户端分级与跨平台（v1.x/v2 起）
- **Tier A 全功能低延迟主控**：Android（v1 首发）、iOS、Windows/macOS/Linux 桌面（v1.x–v2）。
- **Tier B 受限客户端**：Web（v2，监控/演示/轻控制；无裸 UDP、原始深度流受限）。
- 客户端在 HELLO 中声明 `client_caps`；Agent 按能力降级（不推深度/点云/High 编码等）。
- 协议、能力模型、命令/遥测/模型状态与平台无关；只替换传输/解码/渲染/手柄/发现适配器。
- 详细设计见 [17-cross-platform.md](17-cross-platform.md)。

## 4. 非功能需求

| 类别 | 指标 | 说明 |
|---|---|---|
| 视频延迟 | 720p60 端到端 ≤ 100 ms（目标 ≤ 80 ms）；1080p30 ≤ 120 ms | 同一 5GHz Wi-Fi、无拥塞 |
| 控制延迟 | App 采集→机器人执行 ≤ 40 ms（中位数） | 控制帧 100 Hz |
| 控制频率 | 50–250 Hz 可配，默认 100 Hz | 不随视频帧率变化 |
| 安全响应 | 断链/看门狗 ≤ 400 ms 内安全停车 | 机器人侧独立实现 |
| 视频抗丢包 | 3% 丢包下可恢复（关键帧 ≤ 2 s） | FEC + NACK/重传关键帧 |
| 地图规模 | 单次会话 ≥ 200 m²、≥ 200 万体素 | 5 cm 体素 |
| App 性能 | 100 万点 ≥ 30 FPS，内存 ≤ 400 MB | 中端 2022 年手机 |
| 启动时间 | App 冷启动到可连接 ≤ 2 s；机器人 Agent 到可接受连接 ≤ 5 s | |
| 资源占用 | 机器人端 CPU（1080p30 硬编）≤ 25%（4 核 ARM） | 不含感知算法 |
| 恢复 | 网络恢复后 ≤ 3 s 自动重连；地图增量续传 | |

## 5. 约束与假设

- **v1 仅 Android 客户端**（`minSdk 26`，`targetSdk` 跟随当年最新稳定版）；
  共享层从 M0 起按 **KMP-ready** 设计（不引用平台 API），为 iOS/桌面/Web 迁移预留边界。
- **仅局域网**：不实现 NAT 穿透；不做公网中继。后续如需公网再启用 WebRTC 插件。
- 机器人端为 **Linux（x86_64/aarch64）**，需具备常见视频硬件编码能力之一；无硬编时允许软件编码但标注性能受限。
- **不依赖宇树 SDK**：机器人控制通过“适配器”接入（rl_sar 补丁桥接、ROS 2、自定义 MCU 协议、Mock），本项目自身不链接 unitree_sdk2/unitree_legged_sdk。
- **形态不限**：四足/人形/轮足/机械臂/移动机械臂通过“能力描述 + 适配器 + URDF 模型”接入；
  关节数量、名称、层级由 URDF/能力描述决定，App 不硬编码机型。
- **模型来源**：优先 Agent 下发（带哈希校验）；开发者可本地导入；Agent 不在线执行 xacro 等脚本。
- rl_sar 兼容采用“**最小补丁 + 可选零补丁**”策略：对遥控输入来自 MCU/机器人的机型（如 l4w4）提供网络遥控注入补丁；对通过 `/dev/input/js*` 读手柄的机型可用虚拟手柄零补丁接入。
- 观众/多设备场景不承诺多人同时操控；v1 只允许一个操作员 + 可选只读观察。
- 深度相机以 RealSense / Orbbec / ROS 2 深度话题为参考输入；其他相机通过适配器扩展。
- 开源许可证以 **Apache-2.0** 为目标；依赖需满足该许可与专利政策（见 12-open-source.md）。
- 不承诺 v1 提供 iOS/桌面/Web 客户端；v1.x（M7）交付 iOS/桌面 MVP，v2（M8）交付 Web 受限客户端；
  协议与机器人端保持平台无关，详见 [17-cross-platform.md](17-cross-platform.md)。

## 6. 术语

| 术语 | 含义 |
|---|---|
| Agent | 机器人端常驻进程，负责媒体、控制、遥测、地图、管理接口 |
| App | Android 客户端 |
| 能力描述 / Capability | 机器人自描述的 JSON，包含形态、控制模式、通道、遥测、流、地图能力 |
| 适配器 / Adapter | Agent 内把统一命令翻译为具体机器人 SDK/ROS 2 调用的插件 |
| 通道 / Channel | 控制命令中的规范化通道（如 `body.linear_x`） |
| 控制模式 / Mode | 一组通道与按钮布局的集合（如“速度模式”“关节模式”） |
| 会话 / Session | 一次 App↔Agent 的连接，含加密上下文、能力、流 |
| 地图瓦片 / Map Tile | 机器人侧体素地图的分块单元，用于增量传输 |
| 模型包 / Model Bundle | URDF 转换后的 `model.glb` + `model.json` + 哈希，供 App 渲染 |
| MODEL_STATE | 根位姿 + 关节位置的实时状态消息，用于驱动 URDF 模型 |
| 观察者 / Viewer | 只收视频/遥测、不发控制权限的客户端（v1.1） |

## 7. 成功标准（v1 Release）

1. 同一 App 成功控制至少 **3 种机器人形态**：rl_sar 四轮足（L4W4，实机或 MuJoCo 仿真）、ROS 2 差速底盘、ROS 2 机械臂（或 mock 替代）。
2. 三种常见手柄（Xbox、DualSense、Switch Pro）热插拔可用，两支手柄可同时连接并分配角色。
3. 局域网 720p60 视频端到端延迟中位数 ≤ 100 ms，控制看门狗与急停通过故障注入测试。
4. 深度图实时显示，点云地图可建 ≥ 50 m² 并离线保存/加载。
5. rl_sar 兼容链路可用：App 远程完成 GetUp → Locomotion → GetDown → Passive 全流程，断链/看门狗/E-stop 测试通过。
6. **URDF 模型同步**：加载四足 16 DOF、人形 29 DOF、轮足 16 DOF、机械臂 7 DOF 四类模型，
   30 Hz 状态同步、60 FPS 渲染，关节顺序/限位与 URDF 一致。
7. 对抗验证（见 14-adversarial-verification.md）安全不变式 I1–I11 全部通过；协议 fuzz 24h 无崩溃/无内存错误。
8. 文档、mock 机器人、构建脚本齐全，外部开发者能按文档跑通全链路。
9. **KMP-ready 边界**：`core-protocol` 不依赖 Android API，协议测试向量语言无关，
   C++/Kotlin 双端字节级一致；为 M7（iOS/桌面）与 M8（Web）迁移预留。

### 7.1 跨平台阶段验收（M7/M8）

- M7：iOS 与桌面客户端完成 控制+视频+手柄+URDF 同步；与 Android 共用 `protocol/vectors`。
- M8：Web 受限客户端（WebTransport/WebRTC）完成监控/轻控制/地图查看；能力降级正确。
- 详见 [17-cross-platform.md](17-cross-platform.md)。
