# 10 路线图、任务拆分与风险

> 假设团队 3 人（Android 1、机器人 C++/Linux 1、测试/工具 0.5–1），全职投入。
> 总周期约 20–24 周（MVP 14–16 周 + 硬化 6–8 周）。不依赖宇树 SDK；
> rl_sar 036 为首个真机目标；目标形态覆盖任意四足/人形/轮足/机械臂（URDF 模型驱动）。

## 1. 里程碑

### M0 文档与骨架（1–2 周）

> 可执行任务分解、排期与验收 Runbook见 **[16-m0-plan.md](16-m0-plan.md)**（当前执行入口）。

| 任务 | 交付 | 验收 |
|---|---|---|
| 设计文档评审 | docs/ 全套 + ADR | 评审通过，风险清单确认 |
| 协议 v1 定稿 | 03-protocol 定稿 + 示例 capability | App/Agent 双方可据此开发 |
| 仓库骨架 | android/ agent/ adapters/ tools/ | CI 空跑通过 |
| mock 机器人 | `tools/mock_robot`（UDP+假视频） | App 能连接、看到测试图、控制回显 |

### M1 会话/控制/手柄（3–4 周）

| 任务 | 验收 |
|---|---|
| 发现/配对/会话/加密 | 扫码连接、错误 PIN 限速、重连 |
| 控制帧 + 遥测 + 反馈 | 100 Hz 控制、20 Hz 遥测；看门狗停止 ≤400 ms |
| 手柄抽象 + 多手柄 + 映射 | Xbox/DualSense/Switch Pro 热插拔；双柄槽位 |
| 虚拟手柄 + 死手 + 急停 | 无实体手柄可操作；急停锁存 |
| 能力描述 v1 + 动态 UI | mock 形态切换 UI 正确 |
| 对抗（M1 部分） | 协议 fuzz 初版、会话状态机属性测试 |

### M2 视频链路（3–4 周）

| 任务 | 验收 |
|---|---|
| GStreamer 管线（x86 + RK） | 硬编 720p60/1080p30 可用，软编回退告警 |
| 分片/FEC/pacing/自适应 | 3% 丢包可恢复；带宽自适应 |
| App 解码/SurfaceView | 端到端 720p60 ≤100 ms（目标 80） |
| 统计/HUD/设置 | 延迟/丢包/码率可见可调 |
| 对抗（M2） | 网络损伤矩阵、解码 fuzz、资源竞争 |

### M3 深度、点云与 URDF 模型（4–5 周）

| 任务 | 验收 |
|---|---|
| 深度源 + 编码 + 传输 | 320×240@15 zstd ≤6 Mbps；延迟 ≤150 ms |
| App 深度面板 + GPU 反投影 | 50 万点 ≥30 FPS（目标 60） |
| 机器人体素地图 + 瓦片 | 50 m² 地图 ≤30 s；增量续传 |
| App 地图页 + 测量 + 缓存 | 3D/2D 图层、离线保存 |
| URDF 转换工具 + 模型包 | 四足/人形/轮足/机械臂四类模型可生成、校验哈希 |
| App 模型加载/渲染/状态同步 | MODEL_STATE 30 Hz、60 FPS、关节顺序/限位正确 |
| 对抗（M3） | 深度/瓦片 fuzz、模型篡改/关节错位/网格炸弹 |

### M4 地图与多形态（3–4 周）

| 任务 | 验收 |
|---|---|
| 地图增量/限流/LOD | 断网重连续传；地图不拖垮控制 |
| ROS 2 适配器（差速/机械臂） | Twist/Ackermann/JointTrajectory 控制 |
| capability 生成与校验 | 三形态 UI 自动生成（含 humanoid 形态） |
| URDF 能力派生 + 关节命令 | 从 URDF 生成关节/限位；joint_position 模式通过 |
| 地图投毒/坐标系测试 | 异常数据安全降级 |
| 对抗（M4） | 地图洪泛/投毒、坐标系错误、模型回滚 |

### M5 rl_sar 036 兼容（3–5 周，可与 M2–M4 并行）

| 任务 | 验收 |
|---|---|
| 补丁接口/仲裁/信封 | 036 仿真回放；RC 优先；TTL 零速 |
| 真机网络速度接管 | GetUp→Locomotion→GetDown→Passive 全流程 |
| 安全态/E-stop/状态新鲜度 | 急停 ≤300 ms；状态断流安全 |
| 策略选择/切换/录制 | 0–4 策略切换；MCAP 录制与导出校验 |
| 对抗（R 类） | R-01..R-18 全量；数字孪生 + 台架 |
| 上游 PR/兼容矩阵 | CI 固定 commit 构建 + 补丁重放 |

### M6 硬化与发布（3–4 周）

| 任务 | 验收 |
|---|---|
| 全量对抗验证 | 14 文档 P0 用例全绿；48 h 浸泡 |
| 性能/功耗/热调优 | 30 min 连续稳定 |
| 文档/示例/入门 | 外部开发者按文档跑通 mock 全链路 |
| 打包/签名/发布 | APK + agent 包 + Docker 镜像；SBOM/许可证 |
| 发布评审 | 风险接受 ADR、发布说明、已知限制 |

## 3. 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| rl_sar 分支差异/上游漂移 | 高 | 高 | 兼容矩阵 + 补丁最小化 + CI 固定 commit |
| 036 急停/安全态缺口 | 高 | 高 | 优先补丁 + 台架验证；不通过不实机 |
| Wi-Fi 抖动导致体验差 | 中 | 高 | pacing/自适应/独立流；现场 AP 调优 |
| 手机碎片化/解码问题 | 中 | 中 | 白名单机型 + 能力探测 + 回退 |
| 点云渲染性能不足 | 中 | 中 | LOD/降档/实例化四边形兜底 |
| URDF/模型包解析与同步问题 | 中 | 中 | 哈希/顺序校验；模型仅显示；解析沙箱；不阻塞控制 |
| 深度带宽超预算 | 中 | 中 | 降采样/降频/客户端反投影 |
| 开发资源不足 | 中 | 高 | MVP 范围收敛（单相机/单机器人先通） |
| GPL/专利合规 | 中 | 中 | GPL 隔离；H.264 许可评估；SBOM |
| 安全测试不充分 | 中 | 高 | 对抗验证门禁 + 外部红队评审 |
| 供应链/依赖变化 | 低 | 中 | 锁版本 + 镜像 + 许可证扫描 |

## 4. 发布计划

- `v0.1`（M1）：内测，mock + 单机器人，控制/手柄可用；
- `v0.3`（M2/M3）：视频 + 深度 + 点云，x86 平台；
- `v0.5`（M4/M5）：地图 + 多形态 + rl_sar 036；
- `v1.0`（M6）：安全硬化、对抗验证通过、文档齐全。

## 5. 范围裁剪（若时间不足，按顺序砍）

1. 多相机 → 单 RGB + 单深度；
2. 地图 LOD/大场景 → 局部体素地图；
3. ROS 2 机械臂 → 仅差速底盘 + rl_sar；
4. 录制导出 → 仅录制；
5. WebRTC 插件 → 延后；
6. 120 fps / HDR → 延后；
7. URDF 模型 → 先支持 1–2 个模型，其余用关节条/骨架显示。
