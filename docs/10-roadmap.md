# 10 路线图、任务拆分与风险（B 方案：App + 协议 + CTS + mock/最小参考 Agent）

> 范围收敛决策见 [ADR-0014](adr/0014-scope-app-protocol-cts.md)。机器人端生产实现由厂商/社区按
> [18-protocol-implementation-guide.md](18-protocol-implementation-guide.md) 完成；本项目交付
> **Android App（v1 基础档）+ 协议 v1 + CTS + mock + 最小参考 Agent**。
>
> 假设 2 人全职（Android 1、协议/工具/C++ 1），v1 约 **10–14 周**；v1.1 增强档 **3–4 周**；
> v1.x/v2 跨平台（iOS/桌面/Web）后置，另行规划。

## 1. 交付物总表

| 类别 | 内容 | 版本 |

## 2. 里程碑

### M0 协议与骨架（2–3 周）

| 任务 | 交付 | 验收 |
|---|---|---|
| 协议 v1 定稿 | 03 文档定稿 + `protocol/vectors` ≥60 例 + capability Schema | 三端（C++/Kotlin/Python）向量全绿 |
| 协议内核 | `liburc_protocol`（C++）+ Kotlin `core:protocol` | 帧/CRC/分片/加密/会话向量全绿 |
| 发现与配对骨架 | ANNOUNCE + AUTH + 会话（mock 侧） | App 可发现/配对/连接 mock |
| CTS 框架 | `conformance/` 静态组 + 动态组骨架 | 对 mock 跑通 P0 用例 ≥5 条 |
| mock 服务端 | 全协议模拟 + `--drop/--hold-next-ms/--corrupt-aead/--stale-state` 注入 | 控制/遥测/测试图/看门狗可断言 |
| 最小参考 Agent 骨架 | `reference-agent/`（协议+假数据，无媒体） | 与 App 联调基础会话 |
| App 骨架 | 连接/发现/控制/遥测算 UI（调试屏）+ 测试图直显 | 真机 Wi-Fi 全链路跑通 |
| CI | lint / vectors / agent(x86+aarch64) / android | 四 job 全绿 |

> M0 详细任务、排期与 Runbook 见 [16-m0-plan.md](16-m0-plan.md)。

### M1 基础档（3–4 周）

| 任务 | 验收 |
|---|---|
| 发现：mDNS + UDP 广播 + QR/手动 IP | 三通道可用；配对前不泄露秘密 |
| 会话/配对/加密/单控制者/重连 | CTS P0 配对/会话组全绿 |
| 控制：100 Hz、TTL、死手、越界拒绝 | CTS P0 控制组全绿 |
| 遥测/反馈/链路统计 | 20/50 Hz；HUD 显示 RTT/丢包/FPS |
| 安全：看门狗/E-stop/仲裁/状态机 | 断链 ≤400 ms 停；E-stop 锁存；CTS P0 安全组全绿 |
| 手柄：多型号/多手柄/虚拟手柄/映射 profile | 3 款实体手柄 + 虚拟手柄 |
| 视频：H.264 硬编硬解、分片/FEC/关键帧 | 720p60 端到端 ≤100 ms（LAN） |
| URDF：模型包下载/哈希校验/渲染 + MODEL_STATE | 四足/人形/轮足/机械臂四类模型 60 FPS |
| 能力协商/降级 | 基础档缺失项降级正确 |
| CTS P1 组 | 遥测/视频/模型/故障注入通过 |

## 4. 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 第三方实现碎片化 | 高 | 高 | CTS 强制 + 最小参考 Agent + 实现指南 |
| 无完整 Agent 导致增强档落地慢 | 中 | 中 | 基础档先交付；增强档能力协商；社区共建 |
| 视频/URDF 服务端实现复杂 | 中 | 高 | 参考 Agent 提供可抄实现；CTS 视频/模型组 |
| App 兼容的机器人端质量参差 | 中 | 中 | 能力声明 + 降级 + 实现登记（不背书） |
| 安全语义被实现方忽略 | 中 | 高 | P0 安全组作为接实机门槛；文档明确责任 |
| 跨平台后置导致架构返工 | 低 | 中 | 共享层 KMP-ready、协议平台无关 |
| 单人/资源不足 | 中 | 高 | 范围裁剪（见 §6） |
| 许可证/专利 | 中 | 中 | Apache-2.0 + GPL 隔离 + 编解码评估 |

## 5. 发布计划

- `v0.1`（M0）：协议内核 + mock + App 骨架内测；
- `v0.5`（M1）：基础档全链路（视频/URDF/手柄/安全）；
- `v1.0`（M2）：基础档稳定 + CTS P0/P1 全绿 + 参考 Agent；
- `v1.1`（M3）：增强档（深度/点云/关节命令）；
- `v1.x/v2`：跨平台客户端（后置）。

## 6. 范围裁剪（若资源不足，按顺序砍）

1. 增强档（深度/点云/关节命令）→ 延后；
2. URDF 多模型 → 先 1–2 个模型，其余关节条/骨架；
3. 手柄矩阵 → 先 Xbox/DualSense + 虚拟手柄；
4. 参考 Agent 只保留 x86_64，aarch64 交叉构建保留但目标板验证延后；
5. 桌面端（v1.x）延后到 v2。

## 7. 明确不做（B 方案边界）

- 不提供生产级完整 Agent、多形态适配、rl_sar 补丁、SLAM/点云完整实现；
- 不承诺 v1 的 iOS/桌面/Web 客户端；
- 不承诺 Web 端低延迟主控；
- 不替第三方实现的质量背书（只提供 CTS 与登记）。
