# ADR-0009 对抗验证作为发布门禁

- 状态：Accepted
- 日期：2026-11-18

## 背景

机器人遥操作为安全相关系统；传统“功能测试通过”不足以保证失效安全；
rl_sar 036 已发现多处“文档宣称但未接线”的安全能力（急停、力矩保护、姿态保护、Locomotion→Passive）。

## 决定

- 建立安全不变式 I1–I10 与对抗验证方案（14 文档）；P0 用例未全绿不得发布。
- 每个失败场景固化为自动化/半自动化用例；发布说明附对抗测试摘要与已知限制。
- 接受风险必须写 ADR，明确影响、规避与修复计划。

## 理由

- 安全关键系统需要“主动找反例”，而不是只验证预期路径。
- 已有的 rl_sar 缺口证明“文档≠实现”，必须用源码核对 + 故障注入验证。

## 后果

- 增加测试与红队投入；发布节奏变慢。
- 需要数字孪生与 HIL 台架支撑，早期就要搭建。

## 备选

- 仅功能测试（风险不可接受）。
- 依赖厂商安全认证（本项目为开源原型，不适用）。
