# ADR-0001 默认自研 UDP 传输，WebRTC 作为插件

- 状态：Accepted
- 日期：2026-11-18

## 背景

仅局域网；需要低延迟、多流（控制/遥测/视频/深度/地图）、可定制；需兼顾未来公网扩展。

## 决定

- v1 默认自研 UDP 传输：32 B 统一帧头、按流分端口、控制小包重复、视频分片 + XOR FEC、
  地图请求/响应重传、AES-256-GCM。
- 传输抽象为 `ITransport`；WebRTC 作为插件（媒体轨 + data channel），共享同一套协议编解码。

## 理由

- LAN 无 NAT，自研协议开销最小、完全可控、深度/地图可定制；无需 libwebrtc 的复杂度与体积。
- WebRTC 的拥塞/加密/ICE 优势在公网才明显；插件化保留升级路径。

## 后果

- 需要自己实现 FEC/重组/拥塞/加密，测试成本高（用 14 文档对抗验证覆盖）。
- 未来加 WebRTC 时需处理两套传输的差异与降级。

## 备选

- 纯 WebRTC（复杂度/体积高，深度/地图适配受限）。
- RTP/RTSP（地图/控制仍需另开协议）。
