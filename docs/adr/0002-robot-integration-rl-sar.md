# ADR-0002 不依赖宇树 SDK；以 rl_sar 为第一兼容目标

- 状态：Accepted
- 日期：2026-11-18

## 背景

用户目标机器人包含 rl_sar 036（L4W4，四轮足），其真机遥控来自 MCU UDP 状态帧而非
`/dev/input/js*`；要求不绑定宇树 SDK；多形态机器人需要统一接入方式。

## 决定

- 本项目不链接任何厂商 SDK；机器人控制抽象为 `IRobotAdapter`。
- rl_sar 兼容采用“网络遥控注入补丁 + 状态回传 + 可选虚拟手柄兜底”：
  补丁在 `RobotControl()` 内做输入仲裁与安全态；不改 FSM 语义（必要安全缺口除外）。
- 首个真机验收目标为 rl_sar 036 L4W4；上游 rl_sar 作为通用目标。

## 理由

- 036 遥控来自 MCU 私有 UDP，虚拟 uinput 无效；补丁是最小、可控的路径。
- 不链接厂商 SDK 降低许可/版本耦合；rl_sar 自身负责与 MCU/SDK 通信。

## 后果

- 需维护 rl_sar 补丁与兼容矩阵（上游漂移风险）。
- 036 的安全缺口（急停未接线、Locomotion→Passive 注释、TorqueProtect 无动作）必须由补丁补齐，
  未完成前不允许实机运动测试。

## 备选

- 虚拟手柄（036 真机不可用）。
- MCU 中间人改写（脆弱，仅测试）。
- 直接集成厂商 SDK（违背约束，耦合高）。
