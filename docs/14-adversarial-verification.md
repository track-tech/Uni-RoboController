# 14 对抗验证方案（Adversarial Verification Plan）

> 本文回答一个问题：**凭什么相信这套系统在任何单点失效、恶意输入、误操作和恶劣网络下都不会让机器人失控？**
> 它是设计评审、测试计划与发布门禁的合并文档；v1 发布前必须给出完整执行记录。
> 本文不涉及具体代码实现，只定义验证目标、方法、场景、工具与通过标准。

## 1. 目标与原则

### 1.1 目标

1. **找反例**：主动攻击设计假设，证明“系统会以不可接受的方式失败”，然后修掉。
2. **可度量**：每个安全声明都对应可观测指标与通过/失败判据，不依赖“试了没问题”。
3. **可回归**：失败场景固化为自动化用例，进入 CI/周回归，防止回归。
4. **可追溯**：每个风险有编号、责任人、状态（修复/缓解/接受），接受风险需 ADR 记录。

### 1.2 原则

- **对抗视角优先**：先假设“设计是错的”，再寻找能让机器人危险、失联、误动作、泄密的路径。
- **失效安全（fail-safe）优先于功能正确**：任何不确定状态默认进入安全态。
- **测试极值，不只测典型值**：0、负数、NaN、Inf、最大值、乱序、重放、时钟回拨。
- **物理与数字分离**：软件无法保证物理安全，最终安全由机器人侧硬件/固件看门狗兜底；测试要验证“软件失效时物理兜底是否生效”。
- **诚实记录**：无法验证的声明（例如某个未测机型）必须显式标注，不能默认为通过。

## 2. 安全不变式（Invariants）

| 编号 | 不变式 | 观测点 | 通过标准 |
|---|---|---|---|
| I1 | 无有效控制输入超过 `T_wd` 后，机器人进入安全态（零速/被动/阻尼），且不晚于 `T_wd + 100 ms` | 机器人侧监控（FSM/命令/关节速度）+ 外部录像 | `T_wd=300 ms`，P99 停止延迟 ≤ 400 ms |
| I2 | 无论输入内容如何，适配器输出命令都在能力声明与硬件限幅内 | Agent 命令日志、rl_sar 力矩/位置日志 | 越界样本 0；越界必须被拒绝并计数 |
| I3 | E-stop 一旦触发即锁存，必须显式复位；E-stop 路径不依赖 App/视频存活 | App、Agent、rl_sar、机器人侧 | 从触发到进入被动 ≤ 300 ms；锁存期间无法被任何输入解除 |
| I4 | 控制/配置/地图包不可被重放、篡改、伪造；未配对设备不能控制 | 协议测试、会话测试 | 重放/篡改/未认证样本 100% 拒绝 |
| I5 | RL 策略输出的异常（NaN/Inf/饱和/陈旧/超时）不能导致机器人继续运动 | rl_sar 补丁监控、力矩日志 | 注入异常后 ≤ 300 ms 进入被动 |
| I6 | 同一时刻仅一个控制者；观察者不能发控制 | 会话状态、抓包 | 第二控制者被拒绝或降级为只读 |
| I7 | 视频/深度/地图/日志的资源消耗不影响控制路径的时效 | CPU/带宽/内存监控 + 控制帧间隔 | 在视频/地图满负载下 I1 仍满足，控制 P99 间隔 ≤ 2×周期 |
| I8 | 密钥、配对秘密、日志/录像不泄露到未授权位置 | 存储、网络抓包、日志审计 | 明文密钥 0 处；导出文件无密钥；PUBLISH 前扫描通过 |
| I9 | 时钟跳变/回绕/时间戳异常不会造成误判（重放窗口、看门狗、录制对齐） | 注入时钟攻击 | 不产生误停/漏停；录制可检测异常 |
| I10 | 物理急停/断电/机器人固件超时在任何软件崩溃下仍有效 | HIL 台架物理测试 | 100% 生效（这是最后防线） |
| I11 | 模型包、关节顺序、状态只影响显示/输入提示；不一致时禁止运动渲染与关节命令，不影响安全控制 | 模型/状态注入测试 | 不一致 100% 检出并降级 |

> 每条不变式需要“**反例测试**”：专门构造试图违反它的输入；只做正向测试不算验证。

## 3. 威胁模型与攻击面

### 3.1 攻击者能力假设

| 攻击者 | 能力 | 目标 |
|---|---|---|
| 局域网旁路者 | 可抓包、注入/重放 UDP、ARP/DNS/mDNS 欺骗、洪泛 | 夺取控制、伪造遥测、DoS |
| 恶意/被篡改 App | 任意构造协议帧、越权命令、跳过 UI 限制 | 绕过限幅/急停、重放、注入 |
| 恶意手柄 | 伪造 HID 报告、超范围轴、按键抖动、热插拔风暴 | 误触发动作、越界输入 |
| 本机攻击者（机器人端） | 改配置/模型/日志、杀进程、提权（若已 root） | 使机器人进入不安全状态 |
| 供应链攻击 | 依赖投毒、构建产物替换、OTA 降级 | 植入后门/后门策略 |
| 环境 | Wi-Fi 干扰、AP 掉电、USB/蓝牙干扰、热降频、电源波动 | 触发失效路径 |
| 误操作者 | 急停前松手、切后台、误触、错误配置 | 人为触发危险 |

### 3.2 攻击面清单（STRIDE 简表）

| 面 | 威胁（S/T/R/I/D/E） | 已有/计划缓解 |
|---|---|---|
| UDP 控制/媒体 | 伪造(S)、重放(R)、洪泛(D)、降级(E) | AES-GCM、序号窗口、配对密钥、速率限制、长度校验 |
| 发现/配对（mDNS/广播/QR） | 欺骗(S)、窃取配对秘密(I) | QR 一次性秘密、PIN 限速、配对白名单、可选关闭发现 |
| HTTP 管理 | 未授权(S/E)、路径穿越(I)、上传恶意文件(E) | Token、路径白名单、大小/类型限制、只读挂载 |
| 视频/深度/地图解码 | 恶意码流(RCE/DoS) | 硬件解码隔离、长度/字段校验、fuzz、超时 |
| 手柄输入 | 伪造/越界(T/E) | 输入校验、范围 clamp、死区、按键边沿、防抖 |
| 会话/权限 | 抢占(S)、观察者越权(E) | 单控制者锁、角色校验、心跳 |
| rl_sar/机器人适配器 | 命令注入(T)、参数篡改(E) | 能力声明、双端校验、启动自检、版本校验 |
| 录制/日志/导出 | 泄露(I) | 权限、脱敏、密钥不入日志、导出审计 |
| OTA/依赖 | 降级(E)、投毒(T) | 签名、版本单调、依赖锁定、SBOM |

## 5. 对抗测试矩阵

### 5.1 网络与传输（N）

参数化组合（每个用例固定基线，再叠加变量）：

| 维度 | 取值 |
|---|---|
| 丢包率 | 0 / 1% / 3% / 10% / 30% / 50%（随机 + 突发 burst） |
| 延迟 | 0 / 5 / 20 / 50 / 100 / 300 ms |
| 抖动 | 0 / 5 / 20 / 100 ms（正态/均匀） |
| 乱序/重复 | 1% / 5% / 20% |
| 带宽 | 100 / 20 / 5 / 1 Mbps；视频/控制共存 |
| MTU | 1500 / 1200 / 576 / 分片黑洞 / ICMP 不可达 |
| 断连 | 1 s / 5 s / 30 s；AP 掉电；Wi-Fi 切换；IP 变化（v1 不承诺） |
| 洪泛 | 小包 PPS 10k/100k；畸变包；广播风暴 |

工具：Linux `netns` + `veth` + `tc netem/tbf`、`iptables/nftables`、Scapy、`iperf3`；
Android 侧用 `adb shell` 或路由器侧注入。

通过标准：
- I1 在所有组合下满足；不允许机器人“持续动作”超过 400 ms。
- 视频允许降级/花屏，但不得拖垮控制；控制通道错误率有界。
- 3% 丢包下视频恢复 ≤ 2 s；不允许因 FEC/NACK 逻辑导致内存增长。

### 5.2 协议 / 会话 / 加密（C）

1. **Fuzz**：对每个解析器（帧头、控制帧、遥测、视频分片、深度、地图瓦片、capability JSON、
   配置 YAML、HTTP 请求）做覆盖引导 fuzz（libFuzzer/AFL++），24 h 无崩溃、无 OOB、无未捕获异常。
2. **重放/篡改**：录制合法帧，重放、改字节、改序号、改会话 ID、改时间戳。
3. **降级/绕过**：关闭加密协商、伪造版本、跳过认证、伪造能力描述。
4. **DoS**：半开连接、洪泛、超大 JSON/瓦片、慢速 HTTP、mDNS 投毒。
5. **配对**：错误 PIN 限速、QR 秘密轮换、重复配对、撤销配对后重连。

通过标准：未认证/重放/篡改样本 100% 拒绝；fuzz 0 crash；DoS 下控制不受影响（或安全停车）。

### 5.5 rl_sar / RL 策略（R）

| 用例 | 注入 | 期望 |
|---|---|---|
| R-01 | 在 L4W4 按 `LB_RB`（README 宣称急停） | 当前会失败（RL-01）→ 补丁后必须进入急停 |
| R-02 | 断链（App 侧） | rl_sar 补丁 300 ms 超时→被动；MCU 0.5 s 超时清力矩 |
| R-03 | 补丁进程被杀 / 补丁网络断开 | 回退到“无远程输入”配置：被动或物理 RC |
| R-04 | 单向下行断流（MCU→PC 停，PC 仍下发） | 状态新鲜度检查→被动（当前缺失，补丁必须） |
| R-05 | 策略输出 NaN/Inf/超限 | 拒绝/截断；≤300 ms 被动；记录故障 |
| R-06 | 力矩越界（构造动作） | 当前只打印（RL-02）→ 补丁后必须真正保护 |
| R-07 | 姿态超限 | 当前保护被注释（RL-03）→ 补丁/监控生效 |
| R-08 | 配置缺失/字段篡改/模型替换 | 启动自检拒绝；运行中变更需确认 |
| R-09 | 推理卡顿/模型死锁 | 推理看门狗→被动；不允许复用旧动作无限延伸 |
| R-10 | 输出队列积压 | 限制/清空旧输出；不允许陈旧动作执行 |
| R-11 | 控制周期漂移（50→20 ms） | 按 L4W4 实测：20 ms 决策会摔倒 → 监控周期并报警/被动 |
| R-12 | FSM 状态振荡（快速切换） | 切换限速/防抖；不允许在运动态与被动间高频抖动 |
| R-13 | 策略切换（多策略/技能） | 清历史/动作/队列；切换期间安全插值 |
| R-14 | 观测历史错位/维度错误 | 校验 obs 维度与配置一致；不匹配拒绝运行 |
| R-15 | 关节映射/符号错误 | 校验映射表；单关节点动测试；错误映射不允许上机 |
| R-16 | 导航模式与手动命令冲突 | 命令源互斥；切换需显式确认 |
| R-17 | rl_sar 进程崩溃 | MCU 0.5 s 超时；systemd 拉起默认 Passive |
| R-18 | 物理 RC 与网络输入同时操作 | 物理 RC 优先；网络被抑制并提示 |

| M-05 | 坐标系/外参错误 | 校验外参/时间戳；UI 提示；不用于控制 |
| M-06 | 深度/点云时间戳错乱 | 渲染按时间戳，异常丢弃；录制可检测 |
| M-07 | 深度反投影 NaN/除零 | 着色器丢弃无效点；不出现全屏垃圾/崩溃 |
| M-08 | 模型包篡改/哈希不符/版本错配 | 拒绝加载并告警；控制不受影响；日志记录 hash |
| M-09 | 关节顺序/数量与 capability/URDF 不一致 | 不渲染运动、禁止关节命令、诊断提示 |
| M-10 | URDF 限位缺失/错误/关节类型不符 | 禁止关节命令；仅显示；适配器兜底限幅 |
| M-11 | 根位姿/关节状态跳变、时间戳断流 | 冻结/置灰模型；不用于命令；上报过期 |
| M-12 | 超大网格/纹理炸弹/畸形 URDF/GLB/路径穿越 | 解析前限制；沙箱；拒绝并回退骨架显示 |

### 5.7 资源与性能（P）

- CPU：`stress-ng --cpu N` 占满；控制/看门狗仍满足。
- 内存：`stress-ng --vm`；Agent 不 OOM，App 不崩溃。
- 网络：视频 40 Mbps + 地图洪泛 + 控制共存。
- 热：手机/机器人满载 30 min；帧率/延迟退化曲线；温控策略。
- 蓝牙共存：手柄 + Wi-Fi 2.4G/5G 干扰；延迟抖动统计。
- 冷启动/重启：断电重启后进入安全态时间。

### 5.8 供应链 / 运维（O）

- 依赖锁版本、SBOM、许可证扫描（见 12-open-source.md）。
- 构建可复现性：相同 commit 产出哈希一致（尽力）。
- OTA/升级：签名校验、版本不可降级（或降级需确认）、失败回滚。
- 日志/录像：密钥/PII 扫描；导出文件脱敏。
- 密钥轮换/撤销：配对撤销后旧密钥立即失效。

## 7. 状态机与协议形式化验证

1. **会话/看门狗/急停状态机**：用 TLA+/Apalache（或 SPIN）建模：
   - 状态：未配对 → 认证 → 就绪 → 控制中 → 被动/急停（锁存）→ 断线；
   - 属性：`[] (estop_latched -> not_motion)`、`[] (no_input -> eventually passive within T)`、
     `[] (single_controller)`、`[] (replayed_packet -> rejected)`。
2. **属性测试**：用 Hypothesis/PropEr 随机生成合法/非法帧序列，比对参考模型（Python 实现）与
   Kotlin/C++ 实现的行为；差异即缺陷。
3. **差分测试**：App 端协议编解码 vs GCC 参考实现；rl_sar 补丁 vs 物理 RC 注入（同一按键序列）。
4. **模型检查范围**：不追求全系统形式化；只覆盖安全关键状态机与加密/重放逻辑。

## 9. 故障注入工具与环境

### 9.1 数字孪生（无硬件）

- MuJoCo：用户已有 `l4w4_sim2sim`（MuJoCo 扮 MCU，真机 UDP 协议）与 `lowsim`；
  在其上加 `fault_inject`：丢包/延迟/重复/状态断流/命令篡改/时钟偏移。
- rl_sar 仿真：`rl_sim_mujoco` / Gazebo；Agent 以虚拟手柄或补丁接入。
- 网络：Linux `netns` + `veth` + `tc netem`；UDP 代理（Scapy 或自研）做丢包/重放/延迟/改写。
- 手机：Android Emulator（API 26–36）+ 真机；`adb shell am`、Monkey、Frida（测试机）。
- 模型：`tools/urdf_bundle` 生成正常/畸形/超大模型包；模型哈希/关节顺序/状态注入器；
  GLB/URDF 解析 fuzz 语料；本地导入路径穿越样本。

### 9.2 HIL 台架（实机前）

- 机器人架高/垫起/限位；硬件急停；限流电源；防撞围栏；灭火器；操作员持物理急停。
- 台架阶段只跑低速、软限幅更保守的参数；任何对抗测试失败立即降速/停机复盘。
- 真机前必须通过数字孪生全部用例；真机先跑“安全类”用例（急停/看门狗/断链），再跑功能类。

### 9.3 示例命令（Linux）

```bash
# 10% 丢包 + 50ms 延迟 + 20ms 抖动 + 乱序
tc qdisc add dev eth0 root netem loss 10% delay 50ms 20ms reorder 25% 50%
# 突发丢包
tc qdisc add dev eth0 root netem loss gemodel 5% 50% 1% 10%
# 带宽限制
tc qdisc add dev eth0 root tbf rate 5mbit burst 32kbit latency 400ms
# CPU 压力
stress-ng --cpu $(nproc) --timeout 60s
# 实时抖动观测
cyclictest -m -Sp90 -i1000 -l10000
```

## 10. 验收标准与门禁

### 10.1 量化指标

| 指标 | 目标 | 测量 |
|---|---|---|
| I1 看门狗停止延迟 | P99 ≤ 400 ms（T_wd=300 ms） | 机器人侧日志 + 高速录像 |
| E-stop 端到端 | ≤ 300 ms | 人按按钮到关节速度≈0 的录像/日志 |
| 控制帧间隔 | P99 ≤ 2×周期（100 Hz 下 ≤ 20 ms） | Agent/App 时间戳 |
| 3% 丢包下视频恢复 | ≤ 2 s | 客户端统计 |
| fuzz | 0 crash/0 OOM/0 未捕获异常 | 24 h 报告 |
| 协议拒绝率 | 重放/篡改/未认证 100% 拒绝 | 用例统计 |
| 不变式属性测试 | 0 违反（≥10^6 序列） | CI 报告 |
| 资源恶化 | 30 min 满载后 I1 仍满足 | 长稳测试 |

### 10.2 发布门禁

- P0 安全用例（I1–I5、S-01、R-01/R-02/R-04/R-05、S-101、S-109）**必须全绿**；
- 其余用例允许有“已知问题”，但必须有：影响说明、规避方式、修复计划、风险接受 ADR；
- 对抗测试报告 + 录像 + 失败用例清单随 Release 附上；
- 每次 Release 前执行 48 h 浸泡 + 每周对抗回归。

### 10.3 缺陷分级与流程

| 级别 | 定义 | 处置 |
|---|---|---|
| P0 | 可导致失控/伤人/失去急停 | 立即停止发布；24 h 内修复或回滚 |
| P1 | 安全降级、功能阻断、可被远程利用 | 发布前必须修复 |
| P2 | 体验/性能问题，不影响安全 | 排期修复 |
| P3 | 建议/优化 | backlog |

## 11. 组织与节奏

- **红队**（不写业务代码）：每周 1 次针对新功能的攻击设计 + 场景执行；维护剧本库与工具。
- **蓝队**（开发）：修复、加自动化、写回归；每个 P0/P1 缺陷必须附带复现用例。
- **评审会**：每个里程碑结束做 60 min 对抗复盘：哪些假设被推翻、哪些保护是“纸面的”。
- **持续混沌**：CI 每周跑随机网络损伤 + 随机协议变异；结果看板公示。
- **指标**：不变式违反数、P0/P1 数、平均修复时间、用例覆盖率（场景/协议/机型）。

## 14. 附录

### 14.1 用例模板

```yaml
id: R-05
title: 策略输出 NaN/Inf 注入
layer: rl_sar
preconditions: [机器人架空, 高速录像, 物理急停就位, 补丁监控开启]
steps:
  - 正常进入 RLLocomotion
  - 通过测试注入接口向动作队列写入 NaN/Inf/1e9
  - 持续 2 s 或直到进入被动
expected:
  - 力矩被拒绝/clamp，不出现不可控动作
  - ≤300 ms 进入 Passive 并锁存故障
  - 日志包含故障码与时间戳
metrics: [停止延迟, 最大关节速度, 故障码]
pass_criteria: 停止延迟 ≤300 ms 且无越界力矩输出
```

### 14.2 必须采集的日志字段

- App：控制帧 seq/ts、发送间隔、手柄状态、会话事件、错误码；
- Agent：收包统计、看门狗事件、适配器命令、安全层拒绝记录、地图/视频资源；
- rl_sar patch：输入帧、FSM 切换、状态新鲜度、推理耗时、队列深度、动作统计、故障；
- 机器人：关节 q/dq/tau_est、IMU、MCU 通信统计、固件超时事件；
- 外部：高速录像（≥120 fps）、硬件急停时间戳、网络抓包（同步时钟）。

### 14.3 不可验证项（诚实清单）

- 未覆盖机型的真实 Wi-Fi/芯片行为、未测试手柄的驱动差异；
- 极端物理场景（跌落、碰撞、电池热失控）不在软件验证范围；
- 供应链构建完全可复现性在跨平台下难以 100% 保证；
- 上述项必须在发布说明中列为“未验证/需现场确认”，不得默认为已通过。
