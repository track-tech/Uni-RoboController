# 05 深度图、点云与地图设计

> 核心决策：**传深度图 + 客户端 GPU 反投影生成实时点云**，机器人侧只维护并增量下发**体素地图**。
> 这样带宽比直接传点云小一个数量级，且客户端少一次 CPU 点云解码。
> 线路格式见 [03-protocol.md](03-protocol.md) §7.3/§7.4。

## 1. 为什么传深度而不是传点云

| 数据 | 640×480 原始 | 压缩后（典型） | 30 fps 带宽 |
|---|---|---|---|
| Z16 深度 | 600 KiB/帧 | 90–150 KiB（zstd/预测编码） | 22–36 Mbps（可降到 10–15 Hz） |
| 点云（30 万点，12–16 B/点） | 3.5–4.7 MiB/帧 | 0.15–0.6 MB（Draco） | 36–144 Mbps |
| 结论 | — | — | **深度小 1.6–6.5 倍**，且客户端 GPU 反投影几乎零成本 |

因此 v1 的实时点云 = **深度图 + 内参 + 位姿**在 App 端生成；机器人只下发“累积地图”的增量瓦片。

## 2. 深度源

| 源 | 说明 |
|---|---|
| RealSense D435/D455 | 640×480@30 默认；D455 基线大、远距离更准；USB3 必须 |
| RealSense L515 | 已 EOL，不建议新选型 |
| Orbbec / 其他 | 通过 `IDepthSource` 适配器扩展 |
| ROS 2 深度话题 | `sensor_msgs/Image`（16UC1/32FC1）+ `CameraInfo`；注意 QoS |

注意：D400 系列在 USB2 下大量模式不可用（最低 640×480@15）；上线前用 `rs-enumerate-devices` 核对 USB 速率。
深度图的 0（无效）与饱和值必须在客户端过滤，否则会在原点附近产生垃圾点云。

## 3. 深度帧传输

- 帧头字段见协议 §7.3；默认 **320×240@10 Hz + zstd（level 1–3）**。
- 可选档位：
  | 档位 | 分辨率 | 帧率 | 编码 | 估算带宽 |
  |---|---|---|---|---|
  | 低 | 320×240 | 10 | zstd | 2–4 Mbps |
  | 中（默认） | 320×240 | 15 | zstd | 3–6 Mbps |
  | 高 | 640×480 | 10 | zstd | 8–15 Mbps |
  | 原始 | 640×480 | 15 | raw | 70–150 Mbps（仅调试/有线） |
- 编码：
  - `zstd`：通用、快、无损；作为默认。
  - `RVL/预测编码`：可进一步降低 30–50%，作为 v1.1 可选（需自行实现/移植并验证）。
  - `RGB8 伪彩`：仅用于“只看图”的低带宽模式，不参与点云计算。
  - `HEVC Main10 近无损`：可选，但必须按机型实测 `MediaCodec` 是否支持 Main10，否则回退 zstd。
- 不依赖帧间差分（机器人移动时几乎无效）；靠降采样 + 降频 + 空间压缩控制带宽。

## 4. 客户端点云生成（GPU 反投影）

- 顶点着色器输入：深度纹理（Z16，归一化到 [0,1]）、内参（fx/fy/cx/cy）、`depth_scale`、位姿矩阵。
- 反投影：
  `X = (u - cx) * d / fx`，`Y = (v - cy) * d / fy`，`Z = d`（d = 深度 × depth_scale）。
- 无效点：`d == 0` 或超出量程 → 丢弃（`gl_Position = vec4(2,2,2,1)` 踢出裁剪空间）。
- 颜色：从 RGB 纹理按同一 uv 采样；或按高度/距离伪彩。
- 渲染实现（**Filament 主，GLES 兜底**，见 ADR-0011）：
  - 点云可作为 Filament 的 `PrimitiveType::POINTS` 与 URDF 模型同场景渲染；
  - 若使用 GLES：`GL_POINTS` + `gl_PointSize` + `gl_PointCoord` 圆点，**必须运行时查询 `GL_ALIASED_POINT_SIZE_RANGE`**，
    规范只保证下限 1 px；若上限太小（如 1），改用**实例化四边形 billboard**兜底。
  - `SurfaceView` + 专用渲染线程（`androidx.graphics.opengl.GLRenderer` 或自建 EGL）；Filament 使用其 `UiHelper`/`SurfaceView`。
  - 顶点数据用环形多缓冲（3–4 个 VBO 轮转 / orphaning），避免 `glBufferSubData` 隐式同步卡顿。
  - 帧数据更新 10–15 Hz，渲染 60 Hz；渲染线程只取最新快照（drop-stale）。
  - 点大小按屏幕密度换算；point sprite 硬边，避免排序与 blending。
- 性能目标：50 万点 60 FPS（中端机）；100 万点需视锥裁剪 + 点大小 ≤ 2 px；200 万点必须 LOD。

## 5. 机器人侧点云地图

### 5.1 构建

```
深度 + 相机内参 + 相机→base→map 位姿
  → 反投影为点（去无效/量化）
  → 体素哈希（默认 5 cm）标记占用
  → 脏体素队列
  → 4 m 瓦片（tile）编码
  → 按 App 请求发送增量
```

位姿来源（适配器配置）：

- `odom`：机器人自身里程计/IMU（低成本，会漂移；适合局部地图）；
- `slam`：外部 SLAM（RTAB-Map/FAST-LIO2/激光雷达等）输出位姿或点云；
- `ros2_pointcloud`：订阅外部配准点云，直接体素化（推荐已有 SLAM 的场景）。

v1 不承诺大范围建图精度；地图页明确显示“局部地图/里程计漂移”状态。

### 5.2 瓦片编码（`MAP_TILE`）

| 项 | 设计 |
|---|---|
| 瓦片尺寸 | 4 m × 4 m × 4 m（可配 8 m） |
| 体素 | 默认 5 cm（可 2–10 cm） |
| 坐标 | `u16` 体素索引（0..79）；Morton 排序后做差分 |
| 颜色 | 可选：RGB 打包 u32 或按高度伪彩（不传时客户端着色） |
| 压缩 | zstd（level 1–3） |
| 版本 | `revision` 单调递增；App 按 tile_id 缓存 |
| 增量 | 仅发送“占用状态变化”的体素；删除用墓碑位标记 |

### 5.3 2D 占据栅格

- 从体素投影到 XY 平面（5–10 cm），三态：occupied/free/unknown；每格 2 bit，zstd。
- 用于导航叠加与“哪里能走”的直觉显示；与体素地图同 revision。
- App 作为地面半透明图层渲染。

### 5.4 带宽估算（局域网）

- 首帧全量：200 m² 表面、5 cm 体素 ≈ 8 万体素 × 8–10 B ≈ **0.6–0.8 MB**（<1 s 传完）。
- 增量：机器人 0.5 m/s 移动、每秒新增 1–3 m² 表面 ≈ **0.3–1.2 KB/s**。
- 结论：**地图不是带宽问题，是坐标/时间戳/增量去重与请求调度的正确性问题。**

### 5.5 点云 LOD（大场景可选，v1.1）

- Potree 式八叉树：每节点 1k–10k 点，按屏幕空间误差请求层级；
- App 视锥裁剪 + 距离 LOD；块级 AABB；
- mesh 可选：Marching Cubes → Draco（给“看结构”的模式，带宽更省）。

## 6. 坐标、时间与同步

- 坐标系：`map`（地图原点，会话开始时固定/可重新锚定）、`base_link`、`camera`。
- 所有帧携带采集时间戳（Agent 单调时钟）；App 用同一时钟做延迟估计。
- 深度/点云/位姿必须在同一时间基准；位姿与深度不同步会产生“点云拖影”，需在协议中携带位姿时间戳或按最近邻对齐。
- 录制/回放：保留原始时间戳与到达时间；跨设备时钟偏移由 TIME_SYNC 估计并写入元数据。

## 7. App 地图界面

| 功能 | 说明 |
|---|---|
| 3D 点云 | 旋转/缩放/平移；图层：地图/实时点云/轨迹/机器人位姿 |
| 深度面板 | 伪彩深度图 + 数值（长按取点），可切换原始/降采样 |
| 占据栅格 | 地面半透明层；导航/避障参考 |
| 测量 | 两点距离/高度差（在 3D 中拾取点） |
| 性能 | 点大小/密度/渲染 FPS 可调；低端机自动降档 |
| 持久化 | 瓦片缓存到磁盘（LRU），支持离线回放；保存/加载地图快照 |
| 状态 | 显示地图来源（odom/SLAM）、revision、漂移提示 |

## 8. 验收与风险

### 8.1 验收

- 320×240@15 深度：端到端延迟 ≤ 150 ms，带宽 ≤ 6 Mbps；
- 实时点云 50 万点 ≥ 30 FPS（目标 60），内存 ≤ 400 MB；
- 50 m² 地图建立时间 ≤ 30 s，增量续传正确（断网重连不重复/不丢瓦片）；
- 深度/地图满负载下控制链路 I1 不变式仍满足（见 14 文档）。

### 8.2 主要风险

| 风险 | 缓解 |
|---|---|
| Wi-Fi 抖动（不是带宽） | pacing、drop-stale、独立流、预算只用 70% |
| `gl_PointSize` 上限可能只有 1 | 运行时查询 + 实例化四边形兜底 |
| HEVC Main10 硬解覆盖率不确定 | 编码前探测；默认 zstd 8-bit 路径 |
| 手机热降频 | 点云档位/渲染帧率可调；监测 thermal |
| 时间戳/坐标系不同步 | 统一时钟 + 位姿时间戳 + 录制校验 |
| 深度无效值 | 着色器丢弃；可选中值/置信度过滤 |
| USB2/线材/供电 | 强制 USB3；枚举核对；上线检查 |
| L515 已 EOL | 选型排除 |
| 直接传点云导致带宽爆炸 | 默认“传深度 + 客户端反投影” |
