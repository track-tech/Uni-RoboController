# 多智能体对抗验证流程（Stage Gate）

本目录记录每个执行阶段的 **Brief（方案）→ 对抗评审 → Gate 决策 → 独立审计**。
目的：在写实现代码前，用独立、对抗性的多智能体评审暴露协议、安全、构建与验收缺陷；
**任何阶段未通过 Gate，不得开始该阶段实现**。

## 1. 阶段流程

```
Brief 起草（root）
   → 5 类只读评审 agent 并行攻击（独立上下文）
   → root 汇总去重、修订 Brief
   → Gate：0 P0；P1 关闭或用户书面接受 → PASS
   → 实现（独立 agent/root）
   → 独立审计（非实现者）：复跑验收 + 变异检查
   → 记录 audit 结论
```

- 评审 agent **只读**：不得改代码/文档/配置，不得提交。
- 实现者不得评审自己的阶段；评审不得由实现者授意或代写。
- 最多 2 轮评审；仍有 P0 → 停止并上报用户，禁止以“风险可接受”放行安全 P0。

## 2. 评审角色（每阶段 4 人，S4 加 1 名产品/权限）

| 角色 | 必须攻击的点 |
|---|---|
| 协议/互操作对手 | 帧/CRC/AAD、分片、序号/重放、版本与能力协商、与 CTS/Python 参考的一致性 |
| 安全/失效对手 | 认证/锁定、单控制者、看门狗、急停/复位、状态过期、fail-open、DoS/资源耗尽 |
| 构建/平台对手 | CMake/Gradle、Windows/Linux/aarch64、JDK/SDK 缺失、OpenSSL、CI 矩阵、换行/路径 |
| 测试/范围对手 | 假绿测试、缺失负例、flaky 时序、文档-代码漂移、范围蔓延、验收不可证伪 |

## 3. 严重级别与 Gate

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | 可能导致不安全行为、协议不兼容、数据损坏或安全边界失效 | 必须修复；未修复禁止实现/合并 |
| P1 | 可能导致返工、验收不可信、平台不可用 | 修复，或用户书面接受并记录风险 |
| P2 | 建议/可维护性 | 记录，按需处理 |

**PASS 条件**：0 P0；所有 P1 关闭或有用户接受记录；每条关键行为有可证伪测试；
回滚方案存在；Brief 与现有协议/安全文档的偏差已标注。

## 4. 产物与命名

| 文件 | 内容 |
|---|---|
| `stage-Sx-brief.md` | 阶段方案（目标/范围/接口/不变量/测试/验收/回滚/风险） |
| `stage-Sx-review.md` | 评审汇总（各 agent findings、去重、复现命令） |
| `stage-Sx-gate.md` | Gate 决策（PASS/FAIL、未关闭项、接受人/日期、实现任务） |
| `stage-Sx-audit.md` | 独立审计（复跑证据、变异测试、遗留问题） |

## 5. 对抗评审输出模板

```markdown
## Agent: <角色>
Verdict: PASS | CONDITIONAL | FAIL
### P0
- [ID] 断言 / 证据（文件:行 或 命令）/ 影响 / 建议测试
### P1
...
### P2
...
### 复现命令
```bash
...
```
### 结论
（是否允许进入实现；附条件）
```

要求：至少给出 2 条具体风险，或给出“已攻击 X/Y/Z 均未发现问题”的证据命令；
禁止只写“方案看起来没问题”。

## 6. 变异检查（独立审计必做）

对每个阶段至少破坏 1 个关键不变量，确认测试会失败；否则测试视为不可信：

- 协议：篡改 CRC/AAD/帧头/序号回绕 → 测试必须报错。
- 安全：关闭看门狗/跳过认证/忽略急停 → 安全测试必须失败。
- 构建：删除 `-Werror`/换平台构建失败 → CI 必须拦住。

## 7. 任务板与依赖

- `Sx-review-*`（只读）→ `Sx-implement`（blocked_by 全部 review）→ `Sx-audit`（blocked_by implement）。
- 实现任务必须声明 write scope；阶段之间避免同一目录并行写。
- Gate 记录写入任务描述/评论，作为领取实现任务的前置证据。

## 8. 上报条件

出现以下任一情况，暂停并上报用户：

1. 评审 2 轮后仍有 P0；
2. 需要修改协议/安全语义且影响已发布接口；
3. 本地缺少关键工具链（JDK/SDK/设备）导致验收无法完成；
4. 评审发现范围需要扩大（例如 M0 必须引入 MediaCodec/GStreamer）。
